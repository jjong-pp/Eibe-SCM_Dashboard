# resume

루트 `이전현황.md`가 기기 간 인계의 단일 출처다.
Claude 메모리(~/.claude)와 Codex 메모리는 PC마다 따로 저장되어 다른 PC로 넘어가지 않는다. 넘겨야 할 내용은 전부 저장소 파일에 남긴다.

## A. 기록 — 요청할 때마다 수행
트리거: "이전현황 기록", "현황 정리", "인수인계", "여기까지 저장"

1. 사실을 명령으로 확인한다. 추측으로 쓰지 않는다
   - `git status -sb`, `git log --oneline -5`, 미커밋 파일
   - 루트 검증: `python scripts/verify.py --tests`
   - eibe 검증: `cd eibe && .venv/Scripts/python.exe -m pytest -q --tb=no` (통과·실패 숫자 그대로)
   - 스쿼드: `python scripts/squad.py status`, `.squad/reports/police-log.md` 미해결 경고
2. `이전현황.md`를 갱신한다. 섹션 구조는 유지하고 내용은 덮어쓴다 (이력은 git이 보관)
   | 섹션 | 내용 |
   |---|---|
   | 머리 | 갱신 시각, PC 이름(`hostname`), 브랜치, 기준 커밋 |
   | 1. 저장소 상태 | 원격과의 차이, push 여부, 미커밋 변경 |
   | 2. 이번 세션에 한 일 | 3~7줄 |
   | 3. 검증 상태 | 대상별 명령과 결과 숫자 |
   | 4. 알려진 문제 | 문제, 원인, 위치 |
   | 5. 다음 채팅에서 할 일 | 순서대로, 항목마다 완료 조건 |
   | 6. 사용자 조치 | 사람이 직접 해야 하는 것 |
   | 7. 다른 PC에서 이어받기 | 준비 명령 |
3. eibe 작업이 있었으면 `eibe/docs/STATE.md` 진행 상황도 같이 갱신한다
4. 커밋한다: `docs: 이전현황 갱신 (한 줄 요약)`. push는 사용자에게 확인한다. 다른 PC가 받으려면 push가 필요하다는 점을 함께 알린다
5. 사용자에게 보고한다: 다음 할 일 상위 3개, push 여부

## B. 재개 — 새 채팅이나 다른 PC에서 시작할 때
트리거: "이어서", "재개", "다른 PC에서 시작", 또는 세션 시작 안내에 이전현황 요약이 보일 때 첫 작업 전

1. `git fetch` 후 `git status -sb`로 원격과 비교한다. 원격보다 뒤면 pull할지 사용자에게 확인한다. 미커밋 변경이 있으면 먼저 보고한다
2. `이전현황.md`를 읽고 7절의 PC 준비 상태를 확인한다 (venv, eibe/.venv, eibe/.env, Codex trust)
3. 5절 "다음 채팅에서 할 일" 1번부터 진행한다. 문서와 실제 상태가 다르면 실제 상태를 기준으로 하고 차이를 보고한다

## 원칙
- 숫자, 해시, 파일명은 명령 결과에서 그대로 옮긴다
- 끝난 일은 5절에서 지우고 2절로 옮긴다
- 200줄을 넘기지 않는다. 오래된 세부는 git log에 맡긴다
- 비밀번호, 키, 토큰은 적지 않는다
