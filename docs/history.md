# 에러 해결 및 개선 이력

> 과거 장애 원인과 조치 기록. 비슷한 증상을 만났을 때 참고한다. 현재 유효한 행동 규칙은 AGENTS.md와 스킬에 반영돼 있다.
> 7.15의 `scratch_qa.py`는 이후 `tests/` pytest 스위트로 대체됐다.

## 7. 주요 에러 해결 및 개선 이력 (Error Solving & Refactoring History)

### 7.1. API 무응답 (Hanging) 오류
- **증상:** API 요청 시 5번 이상 시도해도 아예 무반응 상태로 로딩만 지속되며 오류 로그도 없음.
- **원인:** 이전에 실행된 (혹은 비정상 종료된) Uvicorn 서버의 좀비 프로세스가 포트를 점유하여 발생한 데드락.
- **AI 행동 지침:** API 무응답 시 코드 내부 로직을 파헤치기 전에 **가장 먼저 서버 프로세스를 완전히 종료하고 재시작**하여 포트 충돌 여부를 확인할 것.

### 7.2. 전역 폰트 불일치 및 테이블 레이아웃 깨짐 현상
- **증상:** 폼 요소/테이블이 브라우저 기본 폰트로 렌더링되며, 데이터 문자열이 길어지면 테이블 UI가 붕괴됨.
- **원인:** CSS에서 폰트 상속 누락 및 `td`의 텍스트 오버플로우 방어 로직 부재.
- **AI 행동 지침:** 새로운 컴포넌트/테이블 추가 시 반드시 `max-width`, `overflow: hidden`, `text-overflow: ellipsis` 처리를 고려하고 폼 요소 폰트는 전역 변수를 따르도록 할 것.

### 7.3. 비효율적인 UI/UX 로직 (수동 시뮬레이션)
- **증상:** 서버 부하가 없는 프론트엔드 단순 연산임에도 "시뮬레이션 실행" 버튼을 일일이 눌러야 함.
- **AI 행동 지침:** 클라이언트 사이드에서만 이루어지는 가벼운 계산이나 시뮬레이션은 **별도 버튼 없이 실시간(Reactive)으로 즉각 반영**되도록 설계할 것.

### 7.4. Git 버전 관리 동기화 누락
- **증상:** AI가 로컬 코드만 수정하고 Github 원격 저장소에는 반영하지 않음.
- **AI 행동 지침:** 중요한 로직 수정이나 리팩토링 후에는 반드시 사용자의 동의를 구하고 `git add`, `git commit`, `git push`를 통해 코드를 원격 저장소와 동기화할 것.

### 7.5. Uvicorn 무응답 (Hanging) 및 프로세스 데드락 추가 해결
- **증상:** Uvicorn 서버 종료 시 APScheduler가 메인 스레드를 블로킹하여 좀비 프로세스화 됨.
- **원인 및 조치:** `scheduler.shutdown(wait=False)`로 변경하여 즉시 종료 허용.

### 7.6. 파이프라인 및 시스템 모듈 변수 참조 에러 (NameError / AttributeError)
- **증상:** `VALID_INBOUND_STATUSES` 미정의로 인한 크래시, `snapshot.file_path` 오참조로 인한 에러 발생.
- **원인 및 조치:** DB 모델 제약 조건에 맞춘 상수 선언 및 올바른 객체 속성(`snapshot_path`) 참조로 수정.

### 7.7. 시뮬레이션 로직 TypeError 방어 (Null Safety)
- **증상:** 발주 시뮬레이션 중 `pack_qty_per_tu` 필드가 `None`일 때 TypeError 발생.
- **원인 및 조치:** `if (product.pack_qty_per_tu and product.pack_qty_per_tu > 0)`로 Null 가드 강화.

### 7.8. 날짜 파싱 Null Safety 강화 (문자열 처리)
- **증상:** `expiry_date` 등의 날짜 데이터를 파싱할 때 띄어쓰기가 포함되어 있거나 포맷이 일치하지 않아 런타임 에러 발생.
- **원인 및 조치:** `snap.expiry_date.split(" ")[0]` 처리를 추가하여 시간 문자열이 포함되었을 경우에도 안전하게 날짜(Date) 부분만 분리해 내도록 방어 로직 강화.

### 7.9. 엑셀 파싱(parse_excel_file) 시그니처 및 인자 오류 해결
- **증상:** 입고 파이프라인 등에서 엑셀 업로드 시 파일 파싱 과정에서 파라미터 불일치로 인한 오류 발생.
- **원인 및 조치:** `parse_excel_file()` 함수가 `file_bytes` 데이터와 `template_type`을 명확히 전달받도록 함수 시그니처를 수정, 템플릿 검증 및 파싱 로직의 결함을 해결.

### 7.10. 폐기된 모델 참조에 의한 크래시 (InvoiceDB Deprecation)
- **증상:** 재고 자산 계산 시 `InvoiceDB`를 참조하여 NameError 및 API 크래시 발생.
- **원인 및 조치:** `InvoiceDB`는 사용 중지된 스키마. 자산 추적 쿼리가 `InboundDB.payment_amount_krw`를 직접 참조하도록 마이그레이션.

### 7.11. SQLAlchemy 스키마 중복 정의 (Schema Definition Error)
- **증상:** 서버 구동 시 `OutflowHistory` 모델에서 중복된 `product` 관계 설정(Relationship)으로 인한 경고 및 에러 발생.
- **원인 및 조치:** 모델 내 중복된 속성 선언 제거 및 단일 참조로 정리하여 로직 무결성 확보.

### 7.12. 프론트엔드 템플릿 의존성 제거 (Pure HTML/JS Migration)
- **증상:** 프론트엔드와 백엔드 API 분리 원칙 위배 및 렌더링 로직 혼재.
- **원인 및 조치:** `web/templates/`의 Jinja 템플릿 의존성을 완전히 제거하고, 순수 HTML/JS 파일들을 `web/` 루트로 이동시켜 API 지향 설계(Standalone 구조) 강화.

### 7.13. 스키마 참조 오류 (OrderResponse)
- **증상:** `OrderResponse`에서 유효하지 않은 `matched_production_id` 필드를 참조하여 직렬화 에러 발생.
- **원인 및 조치:** `app/schemas.py` 및 `app/routers/pipeline.py`에서 해당 필드 참조를 제거하여 스키마 동기화 문제 해결.

### 7.14. 엑셀 파싱 시 엄격한 컬럼 요구사항 완화
- **증상:** `inventory_snapshot` 엑셀 업로드 시 `updated_at` 컬럼 누락으로 인한 파싱 에러 발생.
- **원인 및 조치:** `app/core/excel_parser.py`에서 불필요하게 엄격했던 컬럼 검증 조건을 완화하여 템플릿 호환성 및 안정성 확보.

### 7.15. E2E 테스트 자동화 (QA Script)
- **개선:** 프론트엔드 및 백엔드 라우트 무결성을 확인하기 위해 200 OK 상태 코드를 전수 검증하는 `scratch_qa.py` 엔드투엔드 테스트 스크립트 작성 및 반영.

### 7.16. 매칭 파이프라인 폐기 및 브랜드(카테고리) 개념 도입
- **개선:** 복잡하고 잦은 에러를 유발하던 3단계(발주-생산-인보이스) 매칭 로직을 폐기하고, 단일 인보이스 리스트 조회/등록 구조로 `matching.html`을 개편.
- **개선:** 전자제품과 식품을 동시에 관리할 수 있도록 마스터 데이터에 `brand_category`를 추가하고, 뷰단에서 브랜드에 따라 '보증기한'과 '유통기한' 텍스트를 동적으로 치환하는 로직 구현.
- **개선:** 설정(`users.html`) 페이지가 지나치게 길어지는 문제를 해결하기 위해, 사이드바 해시 네비게이션(`hashchange`)을 도입하여 소제목 클릭 시 해당 설정 뷰만 표시되도록 SPA 패턴 적용.

### 7.17. UI/UX 용어 통일 및 동적 필터 구조 개선
- **개선:** 혼동을 주던 "인보이스" 용어를 시스템 전반에서 "입고"로 통일하고 사이드바 아이콘을 직관적인 Inbox 아이콘으로 교체.
- **개선:** 기존 하드코딩된 `#brand-tabs` 버튼 네비게이션을 제거하고 API(`/api/products`)와 연동하여 동적으로 `brand_category`를 파싱해오는 `<select id="brand-filter">` 드롭다운 구조로 전면 개편.
- **개선:** `inventory.html` 등에서 하드코딩된 창고 샘플 데이터를 제거하고 `/api/warehouses` 데이터를 기반으로 체크박스 필터를 자동 생성하도록 `buildFilters` 유틸리티 함수 강화.
